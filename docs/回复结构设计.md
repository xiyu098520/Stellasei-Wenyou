# 回复结构 v2 设计稿

> 目标：把「世界状态」从模型文笔里抽出来，变成每回合必出的结构字段。
> 原则：**规则交给代码，文笔交给模型**。能算的不要让模型想，能记的不要让模型猜。

---

## 一、现状盘点（先看清楚已经有什么）

模型当前输出的 JSON（见 `lib/prompt.ts` 第 233 行）：

| 键 | 类型 | 用途 | 状态 |
|---|---|---|---|
| `segments` | `{type, speaker?, tone?, text, ja?}[]` | 演出正文 | 已有 |
| `options` | `string[]`（2–3 条） | 选项 | 已有，**待升级** |
| `threads` | `string[]` | 未兑现伏笔 | 已有 |
| `relations` | `{a,b,state}[]` | 人物关系 | 已有 |
| `plan` | `{scene, cast[]}` | **下一回合**的设想 | 已有 |
| `time` | `string` | 回合结束时的世界时间 → `save.clock` | 已有 |
| `chapter` / `recap` / `memo` | `string` | 按需产出 | 已有 |

**结论：地基已经在了。** 缺的不是「把文字变结构」，而是**三个具体的东西**：

1. 有「时间」，没有「地方 / 天气 / 谁在场 / 你什么样」→ 所以没有背景，没有旁观。
2. 有「下一回合打算去哪」，没有「这一回合推进了什么」→ 所以节奏散、没重点。
3. 有「选项」，但只是字符串 → 不能合并、不能做规则判定。

## 二、新增字段定义

### 2.1 `stage` — 舞台状态（新增）

```json
"stage": {
  "place": "奥赫玛 · 前台大厅",
  "weather": "阴，风从门廊灌进来",
  "present": ["阿格莱雅", "白厄"],
  "look": "新生袍，手里攥着揉皱的通知书"
}
```

| 字段 | 类型 | 规则 | 缺省行为 |
|---|---|---|---|
| `place` | string | 具体到「区域 · 地点」，不超过 12 字 | 沿用上一回合 |
| `weather` | string | 一句，含体感（阴/闷/风大），不超过 14 字；室内可只写"室内" | 沿用上一回合 |
| `present` | string[] | **场上所有能看见的人**，用人物表里的名字，不含主角；最多 8 个 | 沿用上一回合 |
| `look` | string | 主角此刻的衣着与状态，不超过 16 字 | 沿用上一回合 |

> `time` 仍用顶层已有的键，不重复搬进 `stage`。
> 整块给 `null` 或省略 = 沿用上一回合（跟 `threads: []` 同一个套路，省 token）。

**谁消费**：前端「此刻」面板（新增）＋ 系统提示词的下一回合上下文。
**为什么必须结构化**：`present` 是「角色 C 旁观」的唯一可靠来源。靠文笔写"白厄在角落里看着"，模型十回合有八回合会忘；靠字段列出来，下一回合它就必须处理这个人还在场。

---

### 2.2 `beat` — 本回合推进（新增）

```json
"beat": "报到，领到身份卡与宿舍钥匙，被告知东翼封着进不去"
```

- 类型：string，一句话，**不超过 30 字**，写「结果」不写「过程」。
- 不允许为空；不允许写成「继续交谈」「日常」这种什么都没发生的句子。
- 作用：① 前端渲染成一行的「本回合」小结，玩家一眼知道这回合没白过；② 下一回合的 system 里带着它，模型不会原地打转；③ 章末归档时直接当 events 的素材。

> 这一条是治「节奏慢、没重点」的主药。它逼模型每回合回答一个问题：**这回合世界变了什么？**
> 变不了，就说明这回合本来不该单独成一回合。

---

### 2.3 `aside` — 旁观镜头（新增）

```json
"aside": "走廊尽头，白厄靠着墙。视线在通知书上停了半秒，没有过来。"
```

- 类型：string，**每回合 0 或 1 条**，不超过 50 字。
- 硬规则：只能写**可见的动作与位置**，不许写心理（「他心里一沉」禁止），不许写主角看不到的东西，不许推进剧情。
- 场上只有主角一个人时可以省略。
- 前端渲染成独立的一行，灰底、斜体、左侧细竖线，与正文分开——**它是镜头，不是台词**。

> 这就是你要的「角色 C 看着我们，脸上有点不屑」。
> 但要克制：写心理会变成廉价旁白，写动作才像有人真的在旁边。

---

### 2.4 `gained` — 获得物（新增）

```json
"gained": [{ "name": "学生身份卡", "note": "贴着照片，边角还没裁齐" }]
```

- 类型：`{name, note}[]`，每回合最多 3 条；没有就给 `[]`。
- `note` 可选，一句话，不超过 20 字。
- 前端渲染成小卡片，带一个「收进背包」按钮（按钮暂时只做视觉，真正入包是二期）。
- **只为「剧情里明确拿到手」的东西**，不给情绪、不给抽象概念。

> 一期只做展示，不做门槛判定。等你看惯了这些卡，再谈「没卡进不去」。

---

### 2.5 `options` 升级

从：

```json
"options": ["去东翼看看", "问她训练什么时候开始"]
```

改为：

```json
"options": [
  { "text": "去东翼看看宿舍",       "tag": "move" },
  { "text": "问她训练什么时候开始", "tag": "ask"  },
  { "text": "在大厅四处张望",       "tag": "look" }
]
```

| tag | 含义 | 举例 |
|---|---|---|
| `move` | 换地方 | 去东翼、回宿舍、出校门 |
| `ask` | 说话 | 问她、告诉他、顶回去 |
| `act` | 做动作 | 递过去、坐下、推门 |
| `look` | 观察 | 四处张望、看她的眼罩 |
| `wait` | 不动 | 什么都不做，看会怎样 |

- 仍然是 2–3 条。
- **兼容旧数据**：解析时遇到字符串，自动包成 `{text, tag: "ask"}`。
- 前端：每条前面加勾选框，**可多选**；选了 2 条以上时按钮变「发送 N 条」，发送内容按选择顺序用「；」拼成一句玩家意图。
- `tag` 一期只用于展示与合并；二期才用于规则判定（`move` 到某地需要什么、`ask` 是否越过关系阶段）。

## 三、提示词改动（增量，不动现有 21 条规则）

在输出格式示例里加两个键，并在规则区追加 3 条：

```
22. stage 是这一回合结束时的舞台：地点、天气、场上看得见的人（用人物表里的名字，不含主角）、
    主角此刻的样子。整块可以省略 = 沿用上一回合，别每回合重抄。
23. beat 一句话写这回合世界变了什么，不超过 30 字，写结果。写了「继续交谈」「日常」这种
    等于没写，换个能推进的事。aside 是给不在对话里的人的一条镜头，最多一句，只写看得见的
    动作和位置，不许写心理，不许推进剧情，没有就给空字符串。
24. gained 只记这一回合真正拿到手的东西，最多 3 件；options 每条带 tag，从
    move / ask / act / look / wait 里选。
```

**不变的部分**：segments 的 3–6 段、160–260 字、群像规则、第 13 条「不许重演」、第 17 条「每回合有人主动往前推」全部保留。`stage` / `beat` / `aside` 是**在正文之外加的**，不占正文配额。

## 四、渲染草图

### 4.1 正常一屏

```
┌────────────────────────────────────────────────┐
│  第三日 午后 · 奥赫玛 · 前台大厅      阴，风灌进来 │  ← stage.place / time / weather
│  在场：阿格莱雅 · 白厄        手中：学生身份卡     │  ← stage.present / look
├────────────────────────────────────────────────┤
│                                                │
│  │  走廊尽头，白厄靠着墙。视线在通知书上停了      │  ← aside（灰底斜体，左侧细线）
│  │  半秒，没有过来。                             │
│                                                │
│  我把揉皱的通知书递过去。                        │  ← action
│                                                │
│  阿格莱雅：「名字。」                            │  ← line
│                                                │
│  她没抬头，笔尖悬在册子上。                      │  ← narration
│                                                │
├────────────────────────────────────────────────┤
│  本回合　报到，领到身份卡与宿舍钥匙，东翼封着      │  ← beat
│                                                │
│  ▸ 学生身份卡  贴着照片，边角还没裁齐    [收下]   │  ← gained
│  ▸ 门禁卡                                [收下]   │
├────────────────────────────────────────────────┤
│  ☐  去东翼看看宿舍                    (移动)     │  ← options，可多选
│  ☐  问她训练什么时候开始               (询问)     │
│  ☐  在大厅四处张望                     (观察)     │
│                                                │
│               [  发送 2 条  ]                    │
└────────────────────────────────────────────────┘
```

### 4.2 多选状态

```
│  ☑  去东翼看看宿舍                    (移动)     │
│  ☐  问她训练什么时候开始               (询问)     │
│  ☑  在大厅四处张望                     (观察)     │
│         [ 发送 2 条 ]  →  去东翼看看宿舍；在大厅四处张望 │
```

### 4.3 降级形态（模型没吐新字段）

```
┌────────────────────────────────────────────────┐
│  第三日 午后                                     │  ← 只有 time 时，退化成现在的样子
├────────────────────────────────────────────────┤
│  ……正文照常……                                    │
└────────────────────────────────────────────────┘
```

**原则：缺什么就整块不渲染，不显示空壳。** 老存档、模型抽风、中转站截断，都不会让界面裂开。

## 五、成本与风险

| 项 | 估算 |
|---|---|
| 每回合多输出 | `stage`+`beat`+`aside`+`gained` ≈ 70–90 汉字 ≈ 55–70 token |
| 每回合多输入（历史累积） | 同上，一章 24 回合累计约 2000 汉字 ≈ 1500 token |
| 现价折算（0.195 元/百万） | 每回合增量 < 0.00002 元，整章 < 0.001 元 |

**代价可以忽略。风险只有一个**：模型偶尔会把 `beat` 写成空话。对策是前端做一次长度与黑名单校验（「继续」「日常」「交谈」这类词单独成句时标灰），不额外调模型。

---

## 六、验收标准

1. 连续 10 回合，`stage.present` 与正文里真正出现的人**一致**（不多不少）。
2. 连续 10 回合，`beat` 没有一句是「继续交谈 / 日常 / 无事发生」。
3. 场上 ≥2 人时，`aside` 出现率 ≥ 60%，且没有一条写心理。
4. 多选发送后，模型能正确理解合并意图（不把两个动作演成两回合）。
5. 老存档打开无报错，界面自动退化为 4.3。

---

## 七、这一期明确不做

- 手机、通讯录、私聊
- 背包的实际库存与门禁判定
- 货币、物流、历法、数值、骰点
- 关系阶段量化

> 这些全是 `stage` / `gained` 的下游。地基先立住，再往上长。
